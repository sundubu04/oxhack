PHP2Shell idea research

For OxHack's "Time" theme and HRT's data track: what a non-technical end user could use to deal with the PHP2Shell flaws, told as a time-and-data story — and the open gap worth building.

24 Oct 2026End-user focusPassive & legal only

The recommendation

Build "Time to Safe": a live, sourced tracker of whether the sites people use are back and patched, with a predicted safe-by date and a plain "what do I do".

The research found an open slot: councils, the Met Police, Dutch and Finnish government sites, Nintendo and Pokémon all went offline — and no one is tracking which sites are back or patched. The only public checker is a command-line header reader. A sourced, human-readable timeline is missing.

It fits the most prizes from one build: Main (Time) — the whole thing is a race over time; HRT — public data drives a prediction and a decision; plus Snowflake / Tiger Data (the time-series store), Gemini (explain a screenshot or headline), ElevenLabs (speak the verdict), Delta (build in it), Vultr (host it).

The problem, in numbers

~70%of websites run PHP (Wiz headline; W3Techs: 70.3% of known)
21 Octpatches shipped; attempts seen the same day
~1.9M+exposed PHP hosts; counts vary ~10× by method
9.2CVSS v4, both CVEs; unauthenticated RCE

CVE-2026-109618 and CVE-2026-109619 ("PHP2Shell"): unauthenticated remote code execution in PHP core, every version 5.4–8.5. One path is a Heartbleed-style memory leak (heap bytes in a PHPSESSID cookie). A third, CVE-2026-115560, followed on 23 Oct. Found with AI (Wiz, OpenAI, Calif.io) — the story the press is running.

Rules the precedents force (Heartbleed, Log4Shell, HIBP)

  1. 1Never show "safe" from a version header. Distros backport fixes without changing the version number, so the banner lies — show "up to date" only from distro/OSV data, else "unknown".
  2. 2The memory leak changes the advice. Tell a user to change a password only after the site confirms it patched (the Heartbleed rule); sessions and secrets may already be exposed.
  3. 3Lists beat scanners for the public. Build from sites' own statements + passive signals, each with a source and a timestamp, and show when it was last checked.
  4. 4Privacy drives adoption. Check on the user's device or by hash prefix; don't store the list of sites a user cares about.
  5. 5Split advice by role and warn about fake fixes — outages breed scam "fix" sites within hours.

The legal line (UK team)

Both flaws are RCEs and one leaks memory. Actively probing a site you don't own is likely a Computer Misuse Act 1990 offence (and reading leaked memory is a crime — a teen was charged for exactly that with Heartbleed). So the tool:

reads only public data & a normal visit's headers active checks only on a verified-owner's own site tracks what sites said/did, by category never sends exploit-shaped requests never publishes a named unpatched-site list

Decide early

Security-data project, or a vision project?The security idea stacks the most prizes and fits Time + HRT. A Presage (camera-biometrics) project is a different build with a weak Time fit — an either/or. Gemini vision fits the security idea as a feature.
Predict, don't just report.A real time-to-safe prediction with its confidence shown wins HRT; a pretty dashboard of current state does not.
Science-fair format.4–5 min at a table: a fast live demo + one poster beats a slide deck. The demo video doubles as the DEV write-up and the fallback.
Sources & what to not overstate
  • Primary: Wiz, watchTowr, CERT-EU, NCSC UK, Krebs, Malwarebytes (for users).
  • Build-on data (passive/permissive): OSV.dev + distro trackers, endoflife.date, EPSS, wappalyzergo, NCSC-NL list, Pwned Passwords.
  • Precedents: NCSC-NL Log4Shell, HIBP, Mozilla Observatory, Mashable/LastPass Heartbleed lists.
  • Don't overstate: "exploited in the wild" is contested (attempts yes, confirmed compromise no, not in CISA KEV as of 22 Oct); the "8 TLS certs" are the CA eMudhra's, a separate story; "70%" is Wiz's headline, not an independent count; exposure counts vary ~10×.
