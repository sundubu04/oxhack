Clock arm simulator

A 2-link arm — a base angle and an elbow angle — that draws, erases and redraws a clock. This page is the software spec and a live simulation: pick a drawing, tune the link lengths until it fits the arm's reach, and read out the exact joint-angle stream the Raspberry Pi needs. The sim is driven by the same angles the hardware gets, so what you see here is what the arm does.

The pipeline: from "ask Claude" to joint angles

ask Claude "draw a clock"→SVG / polylines→toolpath (x, y, pen)→inverse kinematics→base°, elbow°, pen→Pi → servos

Work in vectors, not pixels. A raster image means edge-detection and contour-tracing (OpenCV / potrace) — slow and fiddly, and the output is still a set of polylines. Claude already speaks vectors: ask it for an SVG path or a JSON list of strokes and you skip the whole computer-vision step. Paste exactly that into the Paste a path box above to see it drawn. So:

Snappy comes from caching: ask Claude once per drawing, store the toolpath, and replay the angle stream. The arm never waits on the model mid-draw.

What software hands the hardware

Software owns the maths (point → angles). The Pi owns angle → servo, with your own calibration — that's the part you said you've got. The contract is a list of waypoints plus a header:

{
  "frame":  "base at origin; x right, y up; angles degrees, CCW from +x; elbow relative to link 1",
  "links_mm": { "L1": 150, "L2": 120 },
  "home":   { "base": 90, "elbow": 0 },      // calibration / park pose
  "pen":    { "up": 0, "down": 1 },           // third actuator (servo or solenoid)
  "feed_mm_s": 140,                            // pen speed; the Pi interpolates between waypoints
  "path": [
    { "base": 46.5, "elbow": 102.8, "pen": 0 },   // travel to the start, pen up
    { "base": 48.1, "elbow": 99.4,  "pen": 1 },   // pen down, drawing
    { "base": 50.0, "elbow": 96.1,  "pen": 1 }
    // ... one entry per waypoint, in order
  ]
}

Use Copy angle stream above to grab this for the current drawing. The Pi reads base, elbow, pen in order and moves at feed_mm_s; it never does kinematics. Keep angular velocity under the servo's limit (slow near full extension, where small moves swing the pen a long way).

The maths (verified)

Forward (angles → pen) and inverse (target → angles) for a 2-link planar arm. Reachable only when |L1−L2| ≤ r ≤ L1+L2; the reach area on the whiteboard is that annulus. There are two elbow solutions (up / down) — pick one and keep it, and watch the fully-extended singularity.

// inverse kinematics: target (x,y) -> base θ₁, elbow θ₂
r2 = x*x + y*y;  r = sqrt(r2);
if (r > L1+L2 || r < |L1-L2|) return OUT_OF_REACH;
c2 = (r2 - L1² - L2²) / (2·L1·L2);
θ₂ = atan2( ±sqrt(1-c2²), c2 );                 // + elbow-up, − elbow-down
θ₁ = atan2(y, x) - atan2(L2·sin θ₂, L1 + L2·cos θ₂);

Checked: forward∘inverse round-trips to ~1e-13 mm over a full clock; out-of-range points return cleanly. Fourier mode runs a DFT on the path and redraws it from the N largest epicycles (N≈40 is plenty for a clock).

Build it in steps

  1. Follow a line. Send the arm two angles and watch it hold a point; then a straight segment between two points. Proves the servo + angle contract end to end.
  2. Pi-turtle a polyline. Convert a list of points to angles and draw an open path (a triangle, your initials). This is the toolpath → IK → angles core, no image needed.
  3. Draw the clock. The parametric preset: circle, ticks, two hands at the current time. Add pen up/down between strokes.
  4. Erase and redraw. Wipe the face and draw the next minute. See the erase options below.
  5. Fourier arm. Redraw a continuous contour from its epicycles — the "Fourier series" look, and smoother motion.
  6. Ask Claude. Prompt → SVG → toolpath → angles, cached so it stays snappy. Draw anything on request.

Erasing — pick one early, it's the real risk

ApproachHowVerdict
Sand tableA ball in sand; drawing a new path covers the old oneNo eraser to fail — the safe build, if the aesthetic suits

Dual-tool headPen and eraser side by side; offset the toolpath by the tool gapTidy, but mind the offset in the maths
Dry-wipe / magnetic boardA slider or the arm clears a magnetic drawing boardClean, but a different surface

In software, erase is just another toolpath: a back-and-forth (boustrophedon) fill over the last drawing's bounding box, with the pen flag set to the eraser tool. Same angle-stream format. The Erase button above animates it.

This page is the frontend sim

It already does what you asked the frontend to do: select a pretrained drawing, control the arm (link lengths, drawing size and height, speed, elbow, Fourier), show the reach area so you can size the links, animate the draw, and erase. Crucially, it runs the pen through the same IK → base°, elbow° that the Pi will, so a drawing that completes here with "out of reach: 0" is one the real arm can make. Export the stream with Copy angle stream and send it down.
